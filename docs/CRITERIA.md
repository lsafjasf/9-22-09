# 收敛判据适用性说明

三种判据都实现同一协议 `is_converged(state) -> bool`，可在
`IterativeSolver(criterion=...)` 处互换，调用点 `solve(A, b, x0)` 不变。
记 `r_k = b - A·x_k`，`r_0` 为初始残差。

## 1. 绝对残差判据 `AbsoluteResidualCriterion(tol)`

停机条件：`||r_k|| <= tol`

- **适用**：`b` 的量级已知且固定（物理单位明确、数据已归一化），
  容差可以直接对应到问题尺度的场景。
- **优点**：阈值语义直观，与问题规模无关地表达“残差本身要多小”。
- **风险**：`b` 量级变化（换单位、换数据）时同一 `tol` 的含义跟着变，
  容易过松或过紧；`||b||` 很大时几乎永远停不下，很小时第 0 步就停。

## 2. 相对残差判据 `RelativeResidualCriterion(tol)`

停机条件：`||r_k|| <= tol * ||b||`

- **适用**：大多数场景的默认选择；希望精度与右端项量级解耦
  （无量纲、尺度不变）时使用。
- **优点**：对 `b` 的缩放不变，换单位/换数据不必重调 `tol`。
- **风险**：`x0` 非零且初猜很好时，`||r_0||` 可能远小于 `||b||`，
  该判据会要求残差压到比初始还低 `tol` 倍，做大量无用迭代；
  反过来初猜极差时可能过早停机。

## 3. 残差下降率判据 `ResidualDecreaseRateCriterion(tol)`

停机条件：`||r_k|| <= tol * ||r_0||`

- **适用**：热启动 / 有良好初猜（`x0 != 0`）的场景，语义是
  “在现有初猜基础上再压低 `tol` 倍”，与 `||b||` 解耦。
- **优点**：停机阈值跟随实际起点，初猜越好停机越早，不浪费迭代；
  `x0 = 0` 时 `||r_0|| = ||b||`，自动退化为相对残差判据
  （`tests/test_combinations.py` 对两者逐位对拍验证）。
- **风险**：`x0` 恰好是真解时 `||r_0|| = 0`，第 0 步即收敛（正确行为，
  已实现且不除零）；若初猜异常地好但解本身需要绝对精度保证，
  应改用绝对判据。

## 选择速查

| 场景 | 推荐判据 |
|---|---|
| 默认、不知道选哪个 | 相对残差 |
| `b` 量级固定且容差有物理含义 | 绝对残差 |
| 热启动 / 非零初猜 / 关心“比起点好多少” | 残差下降率 |
